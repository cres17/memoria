# 하늘 분할 모델

편집기의 하늘 도구는 기본적으로 색과 연결성으로 하늘을 찾는다(`lib/engine/sky_mask.dart`). 사용자가 원하면
U²-Net 기반 분할 모델을 내려받아 더 정확하게 찾을 수 있다. 모델이 없거나 실행에 실패하면 색 기반 방식으로 돌아간다.

## 왜 모델을 쓰는가 (측정)

`test/원본_1.jpg`, `test/원본_2.jpg`에 두 방식을 적용해 비교했다(`ml_pipeline/convert_skyseg.py --photos`).

| 사진 | 색 기반 | 모델 | 비고 |
|---|---|---|---|
| 하늘이 뚜렷한 사진 | 하늘 34.7% | 하늘 31.6% | 두 마스크의 IoU 0.90. 모델 쪽 지평선 경계가 더 매끈함 |
| 하늘이 거의 없는 전차 사진 | 하늘 18.6% | 하늘 0.0% | 색 기반이 건물 벽을 하늘로 잘못 잡음 |

표본이 2장이라 정확도 수치로 일반화할 수 없다. 방향성 확인용이다.

## 출처와 라이선스 (배포 전 확인 필요)

- 가중치: https://github.com/xiongzhu666/Sky-Segmentation-and-Post-processing 의 `skyseg.onnx`
  (SHA-256 `ab9c34c6…89aa1d39`). 저자가 MIT로 공개한 것으로 표기되어 있고, 같은 파일이 Hugging Face의
  여러 저장소(JianyuanWang/skyseg 등)에 MIT로 올라와 있다.
- **학습 데이터는 저자가 밝히지 않았다.** 모델 라이선스(MIT)와 학습 데이터의 이용 조건은 별개다. 상업 배포 전에
  원저자에게 학습 데이터와 이용 조건을 확인하는 것을 권한다. 이 저장소는 그 확인을 대신하지 않는다.
- 원저자 저장소 원문은 이 작업 환경에서 직접 열람하지 못했다(허용 목록 밖). 위 내용은 Hugging Face 저장소 카드와
  재배포 저장소의 설명에 근거한다.

## 변환과 배포

1. `ml_pipeline/convert_skyseg.py`가 ONNX를 받아 SHA-256을 확인하고, 상수 접기 → PyTorch → float16 TFLite로 변환한다.
   입력은 `[1,3,320,320]` RGB 0~1(정규화는 모델에 포함), 출력은 `[1,1,320,320]` 하늘 확률이다.
2. 변환 결과를 원본 ONNX와 같은 사진으로 비교한다(마스크 IoU, 최대 오차). 이 환경에서 하늘 사진 IoU 0.99997,
   하늘 없는 사진 1.0, 최대 확률 오차 0.003이었다.
3. 크기는 약 88MB다. 앱에 넣지 않고 사용자가 하늘 도구에서 내려받는다(`AiManager`가 크기와 SHA-256을 검증).
4. `.github/workflows/sky-model.yml`을 수동 실행한다. 변환·비교·해시 확인을 하고, `publish`를 켜면 릴리스
   `model-sky-u2net-v1`에 올린다. 앱의 `kModelSkySeg`(주소, SHA-256, 크기)가 이 파일과 일치해야 한다.

## 아직 확인하지 않은 것

- 실제 기기에서의 추론 시간과 메모리. 이 환경의 2코어 x86에서 약 0.6초였고, 휴대폰 수치는 측정하지 못했다.
- `flutter_litert`가 이 모델(U²-Net, Resize 38개)을 기기에서 로드하는지. 모델을 릴리스에 올린 뒤 기기 테스트로
  확인해야 한다.
- 학습 데이터 이용 조건.
